# Regression Testcases — TRAI (extension + backend)

Canonical checklist for the project-local regression suite. Run via the
`regression-test` skill (`.opencode/skills/regression-test/SKILL.md`):
`/regression-test` for all cases, `/regression-test <ID>` for one.

Status values: PASS / FAIL / BLOCKED / MANUAL.

| ID | Scenario | Steps | Pass criteria | Notes |
|----|----------|-------|---------------|-------|
| build | Extension + backend build | `npm --prefix extension run build`; `npm --prefix backend run build` | Both exit 0; `extension/dist/manifest.json` carries `name: "TRAI"`; `extension/dist/src/background.js`, `extension/dist/icons/icon{16,32,48,128}.png`, `backend/dist/server.js` exist | Build outputs are gitignored; rebuild after any source change |
| backend | Backend health + auth gate | Probe `GET http://localhost:3000/auth/confirm` (no `/health` route exists; `/auth/*` is the only public path). Tokenless `POST /api/jobs` with a dummy URL | Probe 200; tokenless POST → 401 | Backend port default 3000 (`backend/src/config.ts`); `.env` required; auto-start `npm --prefix backend run dev` when down, stop only recorded PID in cleanup |
| extension | Extension loads in Chrome | agent-browser with `--extension extension/dist`, fresh profile; chrome://extensions shows "TRAI"; extract dynamic extension ID from service-worker link; open `signin.html`, `job.html`, `notice.html` | 3 pages render with source-derived selectors (`#signin-form`, `#start-box`, etc.); `dist/src/content/video-detect.js` bundled; lantern icon renders in toolbar + management page; `extension/dist/icons/icon{16,32,48,128}.png` exist | Never hardcode extension ID — derive per run (chrome://extensions link, or SHA-256 of dist path) |
| signin | Sign in with real account | Open `signin.html`, fill `#email` + `#password`, submit | Navigates to `history.html`; `vtToken` present in `chrome.storage.local` | Credentials live only in the skill file. CAPTCHA/MFA/unexpected challenge → BLOCKED (no bypass). Inbox/email-confirmation steps → MANUAL. Sign-in never auto-starts a job (FR-007) |
| transcribe | Real transcription E2E | Seed `pendingVideo` with `https://www.youtube.com/watch?v=DeKYByRi3gw` via `chrome.storage.local`, open `job.html`, click explicit **Transcribe** button (`#start-transcribe`), poll job until ready | Job reaches `ready`; `#content` shows non-empty transcript within 5 minutes (300 s timeout, backend maxDurationSeconds = 300) | Uses a real account: creates retained history rows + real STT/API usage — run only when approved. Record job ID in Notes. Inbox-dependent flows → MANUAL. Retry via `#retry` → `POST /api/jobs/:id/retry` |
| transcript-actions | Bottom-of-transcript copy + source link (feature 004) | Requires an existing ready transcript (run `transcribe` first or reuse a retained history row): open `history.html`, open a ready row in transcript view; click the Copy button at bottom; paste into a textarea; click the source-video link | Copy button visible at bottom of transcript view; pasted text identical character-for-character to `#content` (no URL/title/timestamps added); success feedback appears and clears on its own; source link visible and opens the exact stored `source_url` in a new tab while the transcript view stays open | No-URL case (link hidden) needs a transcript without `source_url` — construct via DB only, else MANUAL. Link opens in a new tab; the view under test must not navigate. Clipboard permission denial → BLOCKED (feedback check not reproducible) |
